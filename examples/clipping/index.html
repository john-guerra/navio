Navio in a host container that clips

The settings panel is a child of the container you hand Navio, so a page that makes that container a scroll box clips the panel with it. This example is that page: #nv carries an inline overflow-x: auto so its many columns can be scrolled sideways, exactly like a widget inside a narrow dashboard column.

Note overflow-x alone is enough. CSS computes the other axis to auto as soon as one axis is not visible, so a box that only meant to scroll sideways clips vertically too — which is the axis the settings panel needs.
  1. Note the dashed probe: a child of the widget's container sitting 90px below it. The container clips, so you cannot see it. This is the settings panel's situation exactly.
  2. Open the gear. The whole panel is visible and clickable to its bottom edge — Navio lifts the clip off every ancestor while the panel is open (#100).
  3. Close it. The probe is now visible too: the container has stopped clipping, permanently, and the page never asked for that.
What to watch in the readout. The host's inline rule starts as overflow-x: auto. While the panel is open it reads overflow: visible — the shorthand, which replaces the longhand in that inline block. Restoring the shorthand on close therefore removes both axes and the page's own overflow-x: auto never comes back: after one open/close the widget has silently stopped scrolling. Saving and restoring style.overflowX / style.overflowY instead keeps the host's rule intact. A host that sets the rule from a stylesheet rather than inline restores correctly, which is what makes this easy to miss.
